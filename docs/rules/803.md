# 803 bytecode format does not match the assumed interpreter

Severity: low · Confidence: medium · CWE: none

## What it means

The chunk's flavor or version is not the interpreter assumed to run it (5.4 by default, overridable with `analyze(paths, {assume_version = "5.1"})`). It also fires when the version byte names no release at all: the signature is still Lua's, but the file's only statement about its own encoding is one we cannot read. A known older version does not stop the constant table from being read, but an unknown version does, because there is no reader for it.

## Example

The fixture `test/fixtures/bytecode/v51.luac` triggers it: asserted in `test/spec/bytecode_spec.lua` to report 801 with 803 for a 5.1 chunk under the assumed 5.4.

## How to fix

Tell lua-doctor which interpreter the chunk targets via the assume-version option, or rebuild the chunk for the interpreter that actually runs on the device. If the version byte names no release, treat the file as corrupt or hostile and replace it with a known-good build.

## Fix prompt

```prompt
lua-doctor reported 803 (bytecode format does not match the assumed interpreter) at {file}:{line}. Declare the chunk's target interpreter or rebuild the chunk for the interpreter on the device, keeping behaviour the same otherwise, and re-run `lua-doctor {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
