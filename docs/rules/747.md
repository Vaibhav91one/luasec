# 747 hardcoded credential

Severity: high · Confidence: medium · CWE: CWE-798

## What it means

A secret is written into the program: a password, token or key under a credential-like name, or a PEM body carrying key material. The finding never puts the secret itself in the report; it carries the name the value was bound to, a kind, the length and a redacted form. A value the program only compares against, such as a login check, is the check rather than a leak and is not reported.

## Example

From `test/fixtures/secrets/hardcoded_password.lua`:

```lua
local telnet_password = "s3cr3t-pass"
```

## How to fix

Take the credential out of the source: read it from a protected configuration file or the device's secret store at startup, with strict file permissions. Rotate any credential that already shipped in an image, since anyone who unzips the firmware can read it.

## Fix prompt

```prompt
luasec reported 747 (hardcoded credential) at {file}:{line}. Move the credential out of the source into a protected configuration file or secret store and rotate the exposed value, keeping behaviour the same otherwise, and re-run `luasec {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
