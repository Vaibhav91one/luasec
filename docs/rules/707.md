# 707 LuaJIT FFI escape hatch used

Severity: high · Confidence: medium · CWE: CWE-94

## What it means

The LuaJIT foreign-function interface is used, for example reaching C through `ffi.C` or declaring C signatures with `ffi.cdef` (see `test/spec/profiles_spec.lua`, where reaching libc through `ffi.C` is asserted to be a finding on its own). FFI calls leave the Lua sandbox entirely: they are native code with no taint tracking and no sandbox boundary.

## Example

Verified against the analyzer under `--std luajit` (fires 707):

```lua
local ffi = require("ffi")
ffi.cdef("int x;")
```

## How to fix

Remove the FFI use: call a Lua or platform API that already does what the C call did. If native access is truly required, isolate it in a small reviewed module with fixed declarations and fixed call sites, and never let request data choose which symbol is called.
