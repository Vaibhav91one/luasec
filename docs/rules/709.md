# 709 untrusted data reaches command execution

Severity: critical · Confidence: high · CWE: CWE-78

## What it means

Lua Doctor traced untrusted data, such as an HTTP request parameter, into a command execution sink. This is a proven injection, not just a dynamic argument: the finding names the sink, the source, and the trace between them. In firmware this is remote shell execution off a web handler.

## Example

From `test/fixtures/tainted_exec/handler.lua`, asserted in `test/spec/taint_spec.lua` to be exactly one 709:

```lua
local function ping(host)
   os.execute("ping -c1 " .. http.formvalue(host))
end
```

## How to fix

Do not build a shell command from request data; pass fixed arguments, validate against an allowlist, or use an API that does not go through the shell. If a shell is unavoidable, quote every untrusted part with a shell-quoting helper before concatenation. lua-doctor still reports a wholly quoted command, because the flow is real and quoting is easy to get wrong, but one confidence step lower than the same command unquoted, with `sanitizer: shell-quoted` on the finding; a partly quoted command is reported as 712 at full strength.

## Fix prompt

```prompt
lua-doctor reported 709 (untrusted data reaches command execution) at {file}:{line}. Stop building the shell command from untrusted data: use fixed arguments, an allowlist, or a shell-free API, keeping behaviour the same otherwise, and re-run `lua-doctor {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
