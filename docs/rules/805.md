# 805 file is not parseable Lua despite its name

Severity: low · Confidence: medium · CWE: none

## What it means

The file carries a bytecode signature but cannot be read as one: a truncated header, a failed data or integer marker, or a prototype walk that stopped at one of its caps. Each is a property of the parser, not of the input, and the walk never allocates on a claimed length.

## Example

The fixtures `test/fixtures/bytecode/hostile_depth.luac` and `test/fixtures/bytecode/hostile_constants.luac` trigger it: asserted in `test/spec/bytecode_spec.lua` to report 801 and 805, because the prototype walk stops at its caps.

## How to fix

Replace the file with a known-good build: recompile the Lua source with the interpreter that runs on the device and confirm the output scans clean. If the file arrived from outside the build, treat it as hostile and do not load it.

## Fix prompt

```prompt
lua-doctor reported 805 (file is not parseable Lua despite its name) at {file}:{line}. Replace the file with a known-good build compiled for the device interpreter, keeping behaviour the same otherwise, and re-run `lua-doctor {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
