# 724 function containing an execution sink is exposed as an RPC handler

Severity: high · Confidence: medium · CWE: CWE-78
(medium / low when the command is a literal — see below)

## What it means

A function that contains an execution sink is registered as an RPC handler anyone on the network can call, for example a ubus object method or a LuCI dispatch action. The sink becomes remotely reachable. The finding names the sink and the name it is exposed under.

## Example

From `test/fixtures/firmware/ubus_method.lua` (verified to fire 724 alongside 708):

```lua
local object = ubus.add("luci.example")

local function doApply(self, data)
   os.execute(data.command)
end

object.doApply = doApply
```

## When the command is a literal

724 is about the **caller**: the exposure is real whether or not the command can be injected. The severity answer is about the **argument**, and when every argument at the call site folds to a constant, the finding is reported at **medium severity and low confidence** with the note `the command is a literal, so this is an exposure, not an injection`.

This is what a LuCI CBI file writes when it wants to restart a service:

```lua
m.on_after_commit = function()
   luci.sys.call("/etc/init.d/telephony restart")
end
```

Nothing can be put into that command — it is fixed before the program runs. `701` agrees: it requires a non-constant argument and stays silent on the same line. What is left is that a hook the framework runs on a submitted form executes a root command, which is worth a look and is not a remotely reachable RCE. The finding is kept rather than suppressed so that reading is still available.

A local that `const_eval` folds counts as constant, so the module-local spelling is treated the same. A local with a second definition anywhere is **not** constant and the finding keeps its registered severity.

Every argument of the call has to fold, not only the one the sink registry names. `nixio.exec` is registered as taking its command first, but the shell form `nixio.exec("/bin/sh", "-c", c)` takes it third, so requiring the whole argument list is what keeps that shape at its registered severity.

A handler that reaches *any* sink whose command can hold data is reported at the registered severity and names that sink, wherever in the body the literal sits. Downgrading is per handler, not per first sink seen.

## How to fix

For a finding at its registered severity, do not expose sink-containing functions to the network. Remove the handler registration, require authentication and authorization on it, and validate the handler's arguments against an allowlist so remote data cannot reach the sink.

For a downgraded finding the command is already fixed, so there is nothing to inject; the remaining question is whether an unauthenticated caller should be able to trigger it at all. Gate the hook behind authentication, or confirm the service restart is intended to be remotely triggerable.
