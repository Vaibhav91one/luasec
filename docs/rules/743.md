# 743 decoded data fed to an execution sink

Severity: critical · Confidence: medium · CWE: CWE-94

## What it means

Data the program decoded at runtime is handed to an execution sink such as `os.execute` or `dofile`. The decode step hides the payload from static reading, and the sink runs it. An argument the program never decoded is instead a 701, not a decoded payload.

## Example

From `test/fixtures/payload/decoded_exec.lua`, asserted in `test/spec/payload_spec.lua` to fire 743:

```lua
local blob = "2f62696e2f7368"

local function run()
   return os.execute(unpack_bytes(blob))
end
```

## How to fix

Remove the decode-to-sink chain: use the decoded value as data, not as a command, or replace both steps with a fixed, reviewable call. If decoding must stay, keep its output away from every execution sink.
