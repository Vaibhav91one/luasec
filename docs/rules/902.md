# 902 source uses a Lua construct the parser does not support

Severity: low · Confidence: medium · CWE: none

## What it means

The source uses a Lua construct the parser cannot read, such as a backtick command literal or an attribute in a position no Lua version allows. The file is named as the reason it will not parse, so a reader can go look at it. Like the backtick case, the construct may also be a finding in its own right (711).

## Example

From `test/fixtures/rawscan/backtick_command.lua`, asserted in `test/spec/rawscan_spec.lua` to fire 902 naming the construct:

```lua
local who = `id -un`
```

## How to fix

Rewrite the construct in portable Lua the parser reads: replace backtick literals with explicit calls, and move attributes to positions the configured Lua version allows. If the construct is intentional, select the Lua standard that supports it.

## Fix prompt

```prompt
luasec reported 902 (source uses a Lua construct the parser does not support) at {file}:{line}. Rewrite the unsupported construct in portable Lua the parser reads, keeping behaviour the same otherwise, and re-run `luasec {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
