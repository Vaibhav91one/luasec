# 725 sandbox or global environment manipulated

Severity: high · Confidence: medium · CWE: CWE-693

## What it means

The program manipulates the sandbox or the global environment: replacing a function's environment with `setfenv`, installing a metatable on `_G`, or repointing `package.path` or `package.cpath`. In firmware a loader that does this changes what its caller runs and where its modules come from.

## Example

From `test/fixtures/firmware/sandbox_escape.lua`, asserted in `test/spec/firmware_spec.lua` to fire 725:

```lua
local function load_with_blank_env(src)
   local chunk = load(src, "chunk")
   setfenv(1, {})
   debug.setfenv(1, {})
   debug.setmetatable(_G, {__index = function() return nil end})
   package.path = "/tmp/attacker/?.lua"
   return chunk
end
```

## How to fix

Do not replace environments or repoint the module search path at runtime. Run untrusted code with the least privilege the platform offers, keep `package.path` fixed to read-only system directories, and leave the global table alone.
