# 708 execution sink in an exported function that this file never calls and never feeds

Severity: the wrapped sink's severity · Confidence: medium · CWE: CWE-78

## What it means

An execution sink sits in a function other files can call, and nothing in this file feeds it a value luasec can trace. The sink is exposed but the argument is untraceable here, so this is an exposure rather than a proven injection: a 709 would need a visible source. The finding carries the severity of the sink it wraps.

## Example

From `test/spec/taint_spec.lua`, asserted to report 708 rather than silence:

```lua
local function go(host)
   os.execute("ping " .. host)
end
```

## How to fix

Treat the function as a trust boundary: validate the argument at entry against an allowlist, quote it for the shell, or change the interface so callers cannot reach the sink with arbitrary data. If the function is only called with constants, consider making that explicit.

