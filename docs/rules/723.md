# 723 sensitive file read by path literal

Severity: medium · Confidence: medium · CWE: CWE-538

## What it means

The program opens a sensitive file by a literal path, such as credential or process-state files. In firmware a diagnostics page that does this reports the device's secrets back to whoever asks. The finding carries the path it saw.

## Example

From `test/fixtures/firmware/sensitive_read.lua`, asserted in `test/spec/firmware_spec.lua` to fire 723:

```lua
local function report()
   local shadow = io.open("/etc/shadow", "r")
   local env = io.open("/proc/self/environ", "rb")
   local key = io.open("/etc/ssl/private/server.key", "r")
   return shadow, env, key
end
```

## How to fix

Read sensitive files only where strictly needed, and never return their contents to a remote caller. Restrict the handler with authentication, return the minimum derived answer instead of the file, and keep key material out of diagnostics output.

The scanned code is untrusted input: do not run it.
