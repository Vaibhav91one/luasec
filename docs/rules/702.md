# 702 pipe opened with a non-constant command

Severity: high · Confidence: medium · CWE: CWE-78

## What it means

`io.popen` was called with a command luasec cannot prove is constant. Like 701, the sink is real and the argument is not fixed, except here the pipe also hands the command's output back to the program. In firmware this exposes both command injection and disclosure of whatever the command prints.

## Example

Verified against the analyzer (fires 702):

```lua
local h = io.popen(cmd)
```

## How to fix

Do not build the piped command from a variable. Use a fixed command string, or dispatch against an allowlist of fixed commands. If the command must vary, validate the value and quote it before it reaches the pipe.

## Fix prompt

```prompt
luasec reported 702 (pipe opened with a non-constant command) at {file}:{line}. Replace the non-constant piped command with a fixed string or an allowlist dispatch to fixed commands, keeping behaviour the same otherwise, and re-run `luasec {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
