# 711 shell command written as a backtick literal

Severity: high · Confidence: medium · CWE: CWE-78

## What it means

The file contains a shell command written between backticks, a Lua 5.2 command literal the parser behind this tool has never read. It is command execution the normal parse cannot even see, which is why the raw scan reports it. In firmware it is a hidden shell callout.

## Example

From `test/fixtures/rawscan/backtick_command.lua`, asserted in `test/spec/rawscan_spec.lua` to fire 711:

```lua
local who = `id -un`
```

## How to fix

Replace the backtick literal with an explicit, reviewable call: a fixed `os.execute` or `io.popen` string, or better, a Lua or platform API that does the same job without a shell. Do not keep hidden command literals.

## Fix prompt

```prompt
lua-doctor reported 711 (shell command written as a backtick literal) at {file}:{line}. Replace the backtick command literal with an explicit fixed call or a shell-free API, keeping behaviour the same otherwise, and re-run `lua-doctor {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
