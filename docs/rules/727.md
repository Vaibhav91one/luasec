# 727 unbounded string growth can exhaust memory

Severity: medium · Confidence: medium · CWE: CWE-400

## What it means

A loop grows a string or a table once per turn while nothing in the source states a ceiling: not the limit, not the iterator, not the condition. On a memory-poor embedded device this exhausts RAM and kills the process or the box. It is a denial of service by allocation.

## Example

From `test/fixtures/firmware/unbounded_growth.lua`, asserted in `test/spec/firmware_spec.lua` to fire 727:

```lua
local function collect(n, feed)
   local s = ""
   for i = 1, tonumber(n) do
      s = s .. "x"
   end
   return s
end
```

## How to fix

Bound the growth: cap the turn count, cap the accumulator size, and reject or truncate input beyond the cap before the loop runs. Prefer fixed-size buffers or streaming the output instead of accumulating it.
