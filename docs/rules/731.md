# 731 untrusted data written into an HTTP subrequest

Severity: high · Confidence: high · CWE: CWE-444

## What it means

Request data reaches the options table of `ngx.location.capture`, so a
subrequest goes out with an attacker-chosen body or an attacker-chosen header.
That is the Lua surface of
[CVE-2020-11724](https://nvd.nist.gov/vuln/detail/CVE-2020-11724), fixed in
commit `9ab38e8ee35fc08a57636b1b6190dca70b0076fa`; on a module older than
0.10.16 the subrequest request line and headers are framed from the caller's
data, which is HTTP request smuggling (CWE-444).

This is deliberately **not** `730`. A CRLF in a header value splits one response
into two; attacker-chosen framing in a *second*, internally-issued request
desynchronises the proxy and the upstream as to where one request ends and the
next begins, which is a different and generally worse consequence. Both are
worth reporting, and an operator triaging a proxy plugin needs them apart, so
they are apart.

Both the `body` and the `headers` of the options table are checked; a constant
`method` is not a finding, and neither is a subrequest called with only a URI.

## Example

A proxy handler forwards the caller's form body to an upstream API:

```lua
local payload = ngx.req.get_post_args()
ngx.location.capture("/api/forward", {method = "POST", body = payload})
```

This fires with `--std openresty`.

## How to fix

Do not forward caller data as the framing of another request. Proxy at the
nginx layer (`proxy_pass`, `proxy_set_header`) rather than re-issuing a request
from Lua, or pin the subrequest to values the handler chooses and pass the
caller's data as a body of fixed structure that cannot contain a request line.

If the subrequest must carry caller data, constrain it before the call:

```lua
local payload = ngx.req.get_post_args()
ngx.location.capture("/api/forward",
   {method = "POST", body = ngx.encode_args({q = tostring(payload.q)})})
```
