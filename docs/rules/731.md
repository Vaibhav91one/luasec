# 731 untrusted data written into an HTTP subrequest

Severity: high · Confidence: high · CWE: CWE-444

## What it means

Request data reaches the options table of `ngx.location.capture`, so a
subrequest goes out with an attacker-chosen body or an attacker-chosen header.
That is the Lua surface of
[CVE-2020-11724](https://nvd.nist.gov/vuln/detail/CVE-2020-11724), which NVD
records as HTTP request smuggling in `ngx_http_lua_subrequest.c` in **OpenResty
before 1.15.8.4**, and classifies CWE-444 (CVSS 3.1 7.5 high).

The fix is commit `9ab38e8ee35fc08a57636b1b6190dca70b0076fa`, which OpenResty
carries in its bundle as the patch file
`ngx_http_lua-0.10.15-fix_location_capture_content_length_chunked.patch`. That
filename names the module version OpenResty *bundles*, not where the commit sits
in the module's own history: the compare `v0.10.16...9ab38e8` reports the commit
two ahead of v0.10.16, so it is in neither 0.10.15 nor 0.10.16. That is why NVD
scopes the CVE to an OpenResty release rather than to a module version, and it
is why this rule keys on the data flow and names no version of its own.

What the fix changes is message *framing*, not the request
line: the subrequest used to inherit the parent's `Content-Length` by way of a
helper that also forwarded the parent's other headers, and now crafts its own
`Content-Length` and skips copying the parent's when the parent is not chunked.
The smuggling its four regression tests exercise ("avoid request smuggling
1/4" … "4/4") is a request carrying both `Content-Length` and
`Transfer-Encoding: chunked` at once, so the proxy and nginx disagree about
where it ends.

This is deliberately **not** `730`. A CRLF in a header value splits one response
into two; attacker-chosen framing in a *second*, internally-issued request
desynchronises the proxy and the upstream as to where one request ends and the
next begins, which is a different and generally worse consequence. Both are
worth reporting, and an operator triaging a proxy plugin needs them apart, so
they are apart.

Both the `body` and the `headers` of the options table are checked; a constant
`method` is not a finding, and neither is a subrequest called with only a URI.

## Example

A proxy handler forwards the caller's form body to an upstream API:

```lua
local payload = ngx.req.get_post_args()
ngx.location.capture("/api/forward", {method = "POST", body = payload})
```

This fires with `--std openresty`.

## How to fix

Do not let caller data into the framing of another request. Proxy at the
nginx layer (`proxy_pass`, `proxy_set_header`) rather than re-issuing a request
from Lua, or pin the subrequest to values the handler chooses and pass the
caller's data as a body of fixed structure that cannot itself parse as a second
request.

If the subrequest must carry caller data, constrain it before the call:

```lua
local payload = ngx.req.get_post_args()
ngx.location.capture("/api/forward",
   {method = "POST", body = ngx.encode_args({q = tostring(payload.q)})})
```
