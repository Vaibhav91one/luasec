# 903 API seen that is not available in the configured Lua standard

Severity: low · Confidence: medium · CWE: none

## What it means

The source uses an API that does not exist in the configured Lua standard, for example the FFI with no standard configured, or a 5.4 attribute such as `<close>` while an older standard is assumed. The finding names the API and its line. Selecting the right `--std` is the usual answer.

## Example

From `test/spec/rawscan_spec.lua` (verified to fire 707 and 903 with no standard configured):

```lua
local ffi = require("ffi")
local C = ffi.C
C.system("id")
```

## How to fix

Configure the Lua standard the code targets, for example `--std luajit` when the FFI is used deliberately. If the API is accidental, replace it with one the target interpreter provides.

## Fix prompt

```prompt
lua-doctor reported 903 (API seen that is not available in the configured Lua standard) at {file}:{line}. Configure the Lua standard the code targets or replace the API with one the target provides, keeping behaviour the same otherwise, and re-run `lua-doctor {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
