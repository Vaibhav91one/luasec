# 701 command execution with a non-constant argument

Severity: high · Confidence: medium · CWE: CWE-78

## What it means

A command execution sink such as `os.execute` was called with an argument lua-doctor cannot prove is constant. The command could be anything at runtime. In firmware this is the shape every shell-injection finding starts from: the sink is real, the argument is not fixed.

## Example

From `test/spec/directive_scope_spec.lua`, where this line is asserted to fire 701:

```lua
os.execute(cmd)
```

## How to fix

Do not build a shell command from a variable. Pass fixed argument strings written out in the source, or dispatch on the value against an allowlist of fixed commands. If the argument must vary, it is a 709/712 question too: validate and quote it.

## Fix prompt

```prompt
lua-doctor reported 701 (command execution with a non-constant argument) at {file}:{line}. Replace the non-constant command argument with a fixed string or an allowlist dispatch to fixed commands, keeping behaviour the same otherwise, and re-run `lua-doctor {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
