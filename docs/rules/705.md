# 705 module name computed at runtime

Severity: high · Confidence: medium · CWE: CWE-94

## What it means

`require` was called with a module name lua-doctor cannot prove is constant. The module that gets loaded is decided at runtime, so anyone who influences the name can redirect the program to attacker-controlled code, including via a repointed `package.path`.

## Example

Verified against the analyzer (fires 705):

```lua
require(modname)
```

## How to fix

Require modules by literal name written out in the source. If several modules are possible, dispatch against an allowlist mapping fixed keys to `require` calls with literal names. Do not pass caller-controlled strings to `require`.

## Fix prompt

```prompt
lua-doctor reported 705 (module name computed at runtime) at {file}:{line}. Replace the computed module name with a literal name or an allowlist dispatch to literal `require` calls, keeping behaviour the same otherwise, and re-run `lua-doctor {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
