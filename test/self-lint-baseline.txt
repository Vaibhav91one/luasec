# luacheck warnings in src/, frozen by #277.

# One line per warning: the path relative to the linted directory, the luacheck
# code, and the name, tab separated. The line number is deliberately not part of
# it, so an unrelated edit above a baselined warning does not turn the gate red.
#
# `make self-lint` fails on any warning not listed here, and on any line here
# that no longer happens - a list that can outlive the warnings it describes is
# a list nobody reads. `make self-lint-bless` re-takes the file; the comment
# block above survives that.
#
# ---------------------------------------------------------------------------
# The 111 and 113 lines are the point of the exercise, and also its
# embarrassment: they are pre-existing leaks of exactly the class #277 is
# about, and they are listed only because that change does not own src/.
# Taking them one at a time is a one-line change each, and the gate will ask
# for the matching lines here to be deleted.
#
#   four real leaks, one missing `local` each, read here at their call sites:
#      luadoctor/engine/parse_context.lua   line_len_available
#      luadoctor/rules/rawscan.lua          resolve_standard
#      luadoctor/rules/rawscan.lua          read_attribute
#      luadoctor/rules/rawscan.lua          read_require_module
#
#   one global write, not a leak of intent: `_ = list` in cli/handoff.lua
#   assigns the global `_` to discard a value. Harmless and still a global.
#
#   two by design. luadoctor/validate/child.lua is not a module: the driver reads
#   the file and concatenates it in front of the payload to build a one-shot
#   `lua -e` program, so `__luadoctor_sandbox` and `__luadoctor_emit` can only meet
#   through globals. `__LUADOCTOR_NONCE` is the same mechanism, a name the driver
#   writes into that program as text.
#
#   three forward references, 113 with no 111 behind them: call_path,
#   fold_call and unread_line are read above the `local function` that defines
#   them. Correct at run time, because a module body runs top to bottom before
#   anything can call into it, and a linter is right to say the name is not
#   lexically bound there.
#
# ---------------------------------------------------------------------------
